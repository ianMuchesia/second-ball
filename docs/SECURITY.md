# Security

What Second Ball protects, how, and what is still open. Every control below is
in the code named next to it; open items are listed as open.

## Data

- **Synthetic only.** Every club, player, match and event is generated by
  `engine/` (seeded, reproducible). No real clubs, players or personal data
  anywhere. Club and player names are invented ([DATASHEET](DATASHEET.md)).
- **Nothing generated is committed.** `.gitignore` excludes `data/`, `demo/`,
  `runs/` and every `*.jsonl`. Regenerate with `make demo` / `make record`.
- The gold eval items (`evals/gold/caught/*.json`) are model drafts about the
  synthetic demo match plus Ian's labels; they hold no personal data.

## Secrets

- Keys live only in `.env` (git-ignored); `.env.example` lists the names with
  no values: `GEMINI_API_KEY`, `FOUNDRY_ENDPOINT`, `FOUNDRY_API_KEY`,
  `FOUNDRY_MODEL`, `FOUNDRY_ANALYST_MODEL`, `MAX_RUN_USD`.
- The Foundry key is sent only as the `api-key` header to
  `{FOUNDRY_ENDPOINT}/openai/v1/chat/completions` (`agents/llm/foundry.py`).
  Error messages carry the API's own error code and message, never the request
  or its headers (tested: `test_http_errors_say_whether_to_retry_and_never_show_the_key`).
- `scripts/foundry_smoke.py` and the recorder print deployment names, token
  counts and cost, never the endpoint or the key.
- Coding agents may not read `.env` or `~/.azure` ([AGENTS.md](../AGENTS.md)).

## Spending (the model is the only paid call)

- **No accidental spend.** Every command that can call a model defaults to the
  free fake model; a real one needs `--provider gemini|foundry` *and* a
  confirmation (or `--yes`), after a free dry run prints the request estimate
  (`agents/llm/guard.py`). A `.env` that names a provider is not enough.
- **Hard cap per run.** A real provider is refused unless `MAX_RUN_USD` is set.
  Before every call `core/budget.py` prechecks the worst case (input counted at
  one token per byte, plus the full output cap) and blocks it if it could pass
  the cap: no request is sent. The first block turns the **kill switch** on;
  the rest of the run airs code templates.
- A model with no price in `agents/llm/prices.py` is blocked before any request
  (a misnamed deployment cannot spend unpriced).
- Tokens a provider bills on a failed call (an answer cut off at the cap) are
  charged too (`ProviderError.usage`), so the cap counts every billed token.
- Details and real figures: [COST.md](COST.md).

## What airs

- **Code computes every number; the model only chooses words.** A code
  Verifier (`agents/pipeline/verifier.py`) checks every line before it can air:
  every number against the code's values, names against the team sheet, who
  leads, whose number it is, counts, comparisons, predictions. A line it
  rejects is retried, then replaced by a code template: a wrong line never airs
  silently, and an overlay is never empty. Accuracy on Ian's labelled drafts:
  [EVAL.md](EVAL.md).
- **Human approval for risky lines.** A line that mentions injuries or the
  referee gets risk tier `high` and waits in the Producer queue until a human
  approves it (`agents/pipeline/producer.py`).
- The Analyst's tools (the football MCP server, `agents/mcp_server/`) are
  read-only over the match's own events.
- Inputs to the model are synthetic match events and code-made facts, never
  user text, so viewers cannot inject prompts.

## The broadcast API (`stream/api`)

- **Judge mode makes zero model calls**: it serves a recorded run bundle.
- Run names must match `^[A-Za-z0-9_-]+$` and have a `meta.json` on disk, so a
  request cannot reach outside `RUNS_DIR`.
- **Writes are switched off in public.** The two write endpoints,
  `POST /api/runs/{run}/producer/{overlay_id}` (approve/reject) and
  `POST /api/runs/{run}/inject-test-error`, follow `PRODUCER_WRITES`: `open`
  (local development, the default), `token` (the `X-Producer-Token` header must
  equal `PRODUCER_TOKEN`, compared in constant time) or `off`. The Docker
  image and the Container App set `off`: both answer 403 and the audit log
  is untouched (tests in `tests/unit/test_api.py`). Even when open they cannot
  call a model or change what a recorded run airs; they append rows to the
  run's append-only audit log.
- **`GET /api/health`** reports only that the app is up and how many runs it
  can read.

## Deployment (`Dockerfile`, `infra/main.bicep`)

- The image serves one recorded bundle and the built screen. It holds no
  secrets: `.dockerignore` keeps `.env` (and every other run) out of the build
  context, and the deployed app never calls a model, so no key is configured
  in Azure.
- It runs as a non-root user; health checks on `/api/health`.
- The Container App is HTTPS only. Its image is public on GitHub Container
  Registry, so Azure holds no registry credentials; being public, the image
  must hold nothing secret: it has only the code, the built screen and the
  recorded run, which was checked for keys and endpoints before publishing.
  Pushing it needs Ian's GitHub token, typed at a prompt, never stored.
- A monthly cost budget on the resource group emails at 50% and 80% of actual
  spend and 100% of forecast.

## Coding agents

[AGENTS.md](../AGENTS.md): agents may not edit `core/` or `tests/spec/`,
loosen or delete tests, read secrets, call a paid API except through
`core/budget.py`, push to main, tag or deploy. Every change runs
`make lint test`; CI runs lint, tests, the web build, a Playwright smoke test
and the contracts drift check.

## Not yet in place

- The deployment is defined and the image tested locally, but it is **not
  deployed yet**; the public URL's behaviour is to be checked after it is.
- `PRODUCER_WRITES=token` (for a private Producer) has no login screen: the
  screen does not send the token, so on a token-protected server the
  Producer's buttons get 401.
- Microsoft Entra ID (keyless) authentication to Foundry: the provider uses an
  API key today (only used when recording, never by the deployed app).
